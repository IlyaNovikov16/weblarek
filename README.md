Стек: HTML, SCSS, TS, Vite

Структура проекта:
- `src/` — исходные файлы проекта
- `src/components/` — папка с JS/TS компонентами

# Интернет-магазин «Web-Larёk»

«Web-Larёk» — это интернет-магазин с товарами для веб-разработчиков, где пользователи могут просматривать каталог товаров, добавлять их в корзину и оформлять заказы. Сайт предоставляет удобный интерфейс с модальными окнами для просмотра деталей товаров, управления корзиной и выбора способа оплаты, обеспечивая полный цикл покупки с отправкой заказов на сервер.

---

## Архитектура приложения (Паттерн MVP)

Код приложения разделен на слои согласно парадигме **MVP (Model-View-Presenter)**, которая обеспечивает четкое разделение ответственности между классами:

1. **Model (Модель)** — слой данных, отвечает за хранение, изменение и валидацию бизнес-данных приложения (`CatalogModel`, `BasketModel`, `BuyerModel`). Модели не зависят от отображения и пользовательского интерфейса.
2. **View (Представление)** — слой представления, отвечает за отображение данных на странице и обработку пользовательских событий DOM (клики, ввод данных). Все компоненты View наследуются от базового класса `Component`.
3. **Presenter (Презентер)** — связующее звено, реализует основную логику приложения. Напрямую связывает слой View и слой Model с помощью событийного взаимодействия через брокер событий `EventEmitter`.

### Событийно-ориентированный подход
Взаимодействие между слоями организовано через событийно-ориентированный подход с использованием брокера `EventEmitter`:
- Компоненты View и классы Model генерируют события при изменении данных или действиях пользователя.
- Презентер подписывается на эти события, обрабатывает их, передает новые данные в модели или вызывает методы перерисовки интерфейса.

## Базовый код

### Класс `Component<T>`
Абстрактный базовый класс для всех компонентов интерфейса (слой View). Инкапсулирует базовую работу с DOM-элементами. Является дженериком и принимает тип данных `T`, передаваемых в метод `render`.

* **Назначение**: создание и базовое управление DOM-элементами компонента.
* **Конструктор**:
  * `constructor(container: HTMLElement)` — принимает ссылку на родительский DOM-элемент компонента.
* **Поля**:
  * `container: HTMLElement` — хранит корневой DOM-элемент компонента.
* **Методы**:
  * `render(data?: Partial<T>): HTMLElement` — обновляет свойства компонента переданными данными и возвращает корневой DOM-элемент.
  * `setImage(element: HTMLImageElement, src: string, alt?: string): void` — безопасная установка источника и описания для изображений.
  * `toggleClass(element: HTMLElement, className: string, force?: boolean): void` — переключение CSS-класса у элемента.
  * `setText(element: HTMLElement, value: unknown): void` — установка текстового содержимого элемента.
  * `setDisabled(element: HTMLElement, state: boolean): void` — управление атрибутом `disabled`.

### Класс `Api`
Базовый класс для отправки сетевых запросов к бэкенду.

* **Назначение**: выполнение HTTP-запросов (GET, POST, PUT, DELETE).
* **Конструктор**:
  * `constructor(baseUrl: string, options: RequestInit = {})` — принимает базовый URL сервера и заголовки по умолчанию.
* **Поля**:
  * `baseUrl: string` — базовый URL-адрес сервера.
  * `options: RequestInit` — объект параметров запроса по умолчанию.
* **Методы**:
  * `get<T>(uri: string): Promise<T>` — выполняет GET-запрос по указанному эндпоинту и возвращает ответ сервера.
  * `post<T>(uri: string, data: object, method: ApiPostMethods = 'POST'): Promise<T>` — отправляет данные на сервер указанным методом.
  * `handleResponse<T>(response: Response): Promise<T>` — служебный метод проверки статуса ответа от сервера и преобразования его в JSON.

### Класс `EventEmitter`
Брокер событий, реализующий паттерн «Наблюдатель» (Observer).

* **Назначение**: организация связи между слоями Model, View и Presenter через события без прямого связывания компонентов.
* **Конструктор**:
  * `constructor()` — инициализирует пустую коллекцию событий.
* **Поля**:
  * `_events: Map<EventName, Set<Subscriber>>` — коллекция событий и подписок.
* **Методы**:
  * `on<T extends object>(event: EventName, callback: (data: T) => void): void` — подписка на событие.
  * `off(event: EventName, callback: Subscriber): void` — отписка от события.
  * `emit<T extends object>(event: string, data?: T): void` — инициализация события с передачей данных.
  * `trigger<T extends object>(event: string, context?: Partial<T>): (data: T) => void` — возвращает функцию-триггер для вызова события.

## Данные и типы данных

В приложении используются две основные сущности: **Товар** и **Покупатель / Заказ**. Все типы описаны в `src/types/index.ts`.

### Описание типов и интерфейсов

* **`TPayment`** — доступные способы оплаты:
  ```typescript
  type TPayment = 'card' | 'cash' | '';
  ```

* **`IProduct`** — структура данных одного товара:
  * `id: string` — уникальный идентификатор товара.
  * `description: string` — подробное описание товара.
  * `image: string` — ссылка на изображение товара.
  * `title: string` — название товара.
  * `category: string` — категория товара.
  * `price: number | null` — стоимость товара (`null` если товар бесценен).

* **`IBuyer`** — данные покупателя:
  * `payment: TPayment` — выбранный способ оплаты.
  * `email: string` — электронная почта.
  * `phone: string` — номер телефона.
  * `address: string` — адрес доставки.

* **`IOrder`** — полный объект заказа, отправляемый на сервер:
  * `payment: TPayment` — способ оплаты.
  * `email: string` — email покупателя.
  * `phone: string` — телефон покупателя.
  * `address: string` — адрес доставки.
  * `items: string[]` — массив ID выбранных товаров.
  * `total: number` — итоговая сумма покупки.

* **`IOrderResult`** — ответ сервера при успехе:
  * `id: string` — ID оформленного заказа.
  * `total: number` — итоговая списанная сумма.

* **`IProductListResponse`** — ответ сервера со списком товаров:
  * `total: number` — общее количество товаров.
  * `items: IProduct[]` — массив объектов товаров.

* **`FormErrors`** — ошибки валидации полей формы:
  ```typescript
  type FormErrors = Partial<Record<keyof IBuyer, string>>;
  ```

## Слои моделей данных (Model)

### Класс `CatalogModel`
Хранит массив всех товаров и выбранный товар для детального просмотра.

* **Назначение**: управление каталогом товаров.
* **Конструктор**:
  * `constructor()` — инициализирует пустой массив товаров.
* **Поля**:
  * `items: IProduct[]` — полный список товаров каталога.
  * `preview: IProduct | null` — товар, выбранный для просмотра в модальном окне.
* **Методы**:
  * `setItems(items: IProduct[]): void` — сохраняет полученные товары в модель.
  * `getItems(): IProduct[]` — возвращает список товаров.
  * `setPreview(item: IProduct): void` — устанавливает выбранный товар для превью.
  * `getPreview(): IProduct | null` — возвращает текущий открытый товар.
  * `getProduct(id: string): IProduct | undefined` — поиск товара по его `id`.

### Класс `BasketModel`
Хранит список товаров, добавленных пользователем в корзину.

* **Назначение**: управление содержимым корзины и расчёт стоимости.
* **Конструктор**:
  * `constructor()` — создает пустой массив корзины.
* **Поля**:
  * `items: IProduct[]` — массив товаров в корзине.
* **Методы**:
  * `getItems(): IProduct[]` — возвращает товары из корзины.
  * `add(item: IProduct): void` — добавляет товар в корзину (если его там нет).
  * `remove(id: string): void` — удаляет товар из корзины по ID.
  * `clear(): void` — полностью очищает корзину.
  * `getTotal(): number` — вычисляет суммарную стоимость всех товаров.
  * `getCount(): number` — возвращает количество товаров в корзине.
  * `inBasket(id: string): boolean` — проверяет наличие товара в корзине.

### Класс `BuyerModel`
Хранит и валидирует данные покупателя.

* **Назначение**: управление формой оформления заказа и проверкой её заполнения.
* **Конструктор**:
  * `constructor()` — инициализирует объект данных с пустыми значениями.
* **Поля**:
  * `data: IBuyer` — текущие данные формы (`payment`, `email`, `phone`, `address`).
* **Методы**:
  * `setData(data: Partial<IBuyer>): void` — обновляет часть или все поля покупателя.
  * `getData(): IBuyer` — возвращает текущий объект данных покупателя.
  * `clearData(): void` — сбрасывает все поля покупателя.
  * `validate(): Record<string, string>` — выполняет проверку полей и возвращает ошибки валидации.

## Слой представления (View)

Все компоненты представления наследуются от `Component<T>`.

### Класс `Page`
Компонент главной страницы приложения.

* **Назначение**: управление отображением сетки товаров, иконки корзины и блокировки прокрутки.
* **Конструктор**:
  * `constructor(container: HTMLElement, events: IEvents)` — навешивает клик на иконку корзины.
* **Поля**:
  * `_counter: HTMLElement` — счетчик количества товаров в корзине.
  * `_catalog: HTMLElement` — контейнер карточек товаров.
  * `_wrapper: HTMLElement` — обёртка всей страницы.
  * `_basket: HTMLElement` — кнопка корзины в шапке.
* **Сеттеры**:
  * `counter(value: number): void` — меняет значение счётчика на иконке корзины.
  * `catalog(items: HTMLElement[]): void` — обновляет список карточек товаров.
  * `locked(value: boolean): void` — блокирует/разблокирует прокрутку страницы при открытии модалки.

### Класс `Card`
Компонент карточки товара.

* **Назначение**: отрисовка карточки товара в каталоге, модальном окне или корзине.
* **Конструктор**:
  * `constructor(container: HTMLElement, actions?: ICardActions)` — настраивает слушатели событий на карточку или её кнопку.
* **Поля**:
  * `_title: HTMLElement` — заголовок товара.
  * `_image?: HTMLImageElement` — картинка товара.
  * `_category?: HTMLElement` — категорийный бейдж.
  * `_price: HTMLElement` — стоимость.
  * `_text?: HTMLElement` — полное описание.
  * `_button?: HTMLButtonElement` — кнопка («В корзину», «Удалить»).
* **Сеттеры/Геттеры**:
  * `id`, `title`, `price`, `category`, `image`, `description` — установка соответствующих свойств.
  * `buttonText(value: string): void` — измененяет текст на кнопке действия.

### Класс `Modal`
Компонент универсального модального окна.

* **Назначение**: отображение любого дочернего контента во всплывающем окне.
* **Конструктор**:
  * `constructor(container: HTMLElement, events: IEvents)` — вешает слушатели закрытия (крестик, оверлей).
* **Поля**:
  * `_closeButton: HTMLButtonElement` — кнопка закрытия.
  * `_content: HTMLElement` — контейнер для внутреннего содержимого.
* **Методы/Сеттеры**:
  * `open(): void` — открывает модальное окно.
  * `close(): void` — закрывает модальное окно.
  * `set content(value: HTMLElement): void` — устанавливает внутренний контент.

### Класс `Basket`
Компонент отображения корзины.

* **Назначение**: отображение списка выбранных товаров, итоговой стоимости и кнопки оформления.
* **Конструктор**:
  * `constructor(container: HTMLElement, events: IEvents)` — навешивает событие клика на кнопку «Оформить».
* **Поля**:
  * `_list: HTMLElement` — список элементов корзины.
  * `_total: HTMLElement` — итоговая сумма.
  * `_button: HTMLButtonElement` — кнопка перехода к оформлению.
* **Сеттеры**:
  * `items(items: HTMLElement[]): void` — обновляет верстку списка товаров.
  * `total(value: number): void` — выводит итоговую цену.

### Базовый класс `Form<T>`
Базовый компонент формы ввода.

* **Назначение**: обработка ввода данных, вывод ошибок валидации и блокировка кнопки отправки.
* **Конструктор**:
  * `constructor(container: HTMLFormElement, events: IEvents)` — отслеживает события `input` и `submit`.
* **Поля**:
  * `_submit: HTMLButtonElement` — кнопка отправки формы.
  * `_errors: HTMLElement` — блок вывода ошибок.
* **Сеттеры**:
  * `valid(value: boolean): void` — делает кнопку отправки активной/неактивной.
  * `errors(value: string): void` — устанавливает текст ошибки.

### Класс `OrderForm` (наследует `Form<IBuyer>`)
Форма выбора способа оплаты и ввода адреса.

* **Поля**:
  * `_cardButton: HTMLButtonElement` — кнопка оплаты картой.
  * `_cashButton: HTMLButtonElement` — кнопка оплаты наличными.
* **Методы/Сеттеры**:
  * `payment(value: TPayment): void` — выделяет активный способ оплаты.
  * `address(value: string): void` — устанавливает адрес.

### Класс `ContactsForm` (наследует `Form<IBuyer>`)
Форма ввода контактов (email и телефон).

* **Сеттеры**:
  * `email(value: string): void` — значение поля email.
  * `phone(value: string): void` — значение поля телефона.

### Класс `Success`
Компонент успешно выполненного заказа.

* **Назначение**: демонстрация суммы списания и кнопка закрытия.
* **Конструктор**:
  * `constructor(container: HTMLElement, actions: ISuccessActions)` — слушает клик по кнопке закрытия.
* **Поля**:
  * `_close: HTMLElement` — кнопка «За покупками!».
  * `_description: HTMLElement` — текст с итоговой суммой списания.

## Слой коммуникации

### Класс `WebLarekApi`
Класс-адаптер для работы с API бэкенда приложения. Использует композицию, принимая экземпляр класса `Api`.

* **Назначение**: получение списка товаров с сервера и отправка заказа.
* **Конструктор**:
  * `constructor(api: IApi)` — принимает объект с интерфейсом `IApi`.
* **Поля**:
  * `api: IApi` — клиент для сетевых запросов.
* **Методы**:
  * `getProductList(): Promise<IProductListResponse>` — выполняет GET-запрос на эндпоинт `/product/` и возвращает список товаров.
  * `orderProducts(order: IOrder): Promise<IOrderResult>` — выполняет POST-запрос на эндпоинт `/order/` для отправки заказа.

## События приложения (Event-driven model)

Связь между слоями осуществляется через брокер событий. Список основных событий:

* `items:changed` — обновление массива товаров в каталоге.
* `card:select` — выбор товара для детального просмотра.
* `preview:changed` — открытие карточки товара в модальном окне.
* `basket:open` — открытие модального окна корзины.
* `basket:add` — добавление товара в корзину.
* `basket:remove` — удаление товара из корзины.
* `basket:change` — изменение состояния корзины.
* `order:open` — переход к оформлению заказа.
* `order:change` — изменение полей формы выбора оплаты и адреса.
* `order:submit` — переход к форме контактов.
* `contacts:change` — изменение полей формы контактных данных.
* `contacts:submit` — отправка заказа на сервер.
* `formErrors:change` — изменение ошибок валидации.
* `modal:open` — открытие модального окна.
* `modal:close` — закрытие модального окна.
